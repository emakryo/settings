# コミット作成

現在の変更を調査・要約し、ユーザーに確認したのちコミット・プッシュを行います。

## 手順

### 1. 変更内容の調査

以下のコマンドを実行して現在の変更を把握してください：

```bash
# ステータス確認
git status

# ステージされていない変更の差分
git diff

# ステージされた変更の差分
git diff --staged

# 最近のコミット履歴（コミットメッセージのスタイル参考用）
git log --oneline -10
```

### 2. 変更内容の要約

調査結果をもとに、以下の形式でユーザーに変更内容を提示してください：

```
## 変更ファイル
- [ファイル名]: [簡潔な変更内容の説明]

## 変更の概要
[全体的な変更内容を1-3文で説明]

## 提案するコミットメッセージ
[Conventional Commits形式のコミットメッセージ]

例: feat(webapp): Add user authentication feature
例: fix(api): Correct validation error in login endpoint
例: refactor(workflow): Simplify task execution logic
```

### 3. ユーザー確認

以下の確認をユーザーに行ってください：

```
この内容でコミット・プッシュしてよろしいですか？

1. はい、このままコミット・プッシュする
2. コミットメッセージを変更する（新しいメッセージを入力してください）
3. 一部のファイルのみコミットする（対象ファイルを指定してください）
4. キャンセル
```

### 4. コミット・プッシュの実行

ユーザーの承認後、以下を実行してください：

```bash
# 変更をステージング（必要に応じて対象を調整）
git add .

# コミット作成
git commit -m "[コミットメッセージ]"

# リモートにプッシュ
git push
```

## 注意事項

- `.env` や認証情報を含むファイルはコミットしないでください
- コミットメッセージは Conventional Commits 形式を推奨します
  - `feat:` 新機能
  - `fix:` バグ修正
  - `refactor:` リファクタリング
  - `docs:` ドキュメント
  - `test:` テスト
  - `chore:` その他の変更
- プッシュ前にリモートブランチの存在を確認し、必要に応じて `-u` オプションを使用してください
